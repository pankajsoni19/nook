# Card keys, short links, and moving cards between boards (lane KEYS)

Operator request: each board gets a short code and each card a human key (MYT-12) shown on the card and copyable; short links `/tasks/MYT-12` that survive a code change; and "Move to another board…" for a card.

Decisions **D710–D716** (D685–D699 belong to lanes PROV and BACKUP2). Threats **T460–T462**. Migration **079** (`board_keys`; 078 was the last released, 080 is the start-dates lane's). HTTP contracts: docs/plan/API_CONTRACTS.md § Tasks → "Board codes, card keys, and moving a card to another board".

## Decisions

- **D710 — Codes and keys.** A board's code is 2–10 of A–Z and 0–9, starting with a letter, stored upper case (`shared/boardKeys.ts`). A card's key is `<code>-<number>`. Keys are read in any case. The board payload sends `board.code` and each card's `number` (the app builds `key`; no per-card string on the wire); card reads, writes, query results, and search hits carry `key`.
- **D711 — Suggested codes.** One word gives its first three characters (Roadmap → ROA), two words the first two of the first and the first of the second (My tasks → MYT), three or more their initials, at most four; leading digits are dropped, and a name without letters suggests BRD. A suggestion is made free with a numeric suffix (MYT2, MYT3, trimming to 10 characters). New board shows the server's free suggestion as the name is typed and keeps the person's own code once they type one. The migration backfills existing boards the same way, oldest first.
- **D712 — Who changes a code, and uniqueness.** Only the owner (the code changes every card's key; managers get 403 OWNER_ONLY). Codes are unique without case over every board that still exists, binned ones included, so a Bin restore never collides; a purged board frees its code. Stricter than "unique among live boards" on purpose.
- **D713 — Numbers and short links.** Each board keeps `next_card_number`; an insert trigger gives every new card the next number (every creation path, and every test fixture, is numbered). Existing cards were numbered in creation order, binned ones included, so a restore keeps its key. Numbers are never reused, after a Bin purge or a move away included. `/tasks/MYT-12` resolves through `GET /api/tasks/keys/:key` and replaces the entry with the card's URL; Copy link copies the short link; the key in the card header copies the key.
- **D714 — Changing a code keeps old keys (alias table).** The old code goes into `board_code_aliases` (code → board): `OLD-12` still resolves to card 12 of that board, and no other board may take the old code (otherwise an old link would silently open someone else's card). The board may take a former code back, which drops that alias. Chosen over per-card key history: one row per code change, whatever the board's size.
- **D715 — Moved cards keep their old keys.** On a move the card's old (board, number) goes into `card_key_aliases` → card. A key resolves to the card with that number on the board its code names now or formerly, else to the card that had it before moving. Old `/tasks/:b/card/:k` links (notifications, mail) follow too: the card dialog sees the card is on another board and replaces the route.
- **D716 — Move to another board.** Can edit on both boards; both board locks are taken in id order (no deadlock between opposite moves). The card lands at the bottom of the chosen column, by default the destination's first column that is not done; WIP and the card cap apply. Rules for board-scoped data:
  - **Hierarchy: refuse rather than move or orphan.** A card with live sub-cards is refused (409 HAS_CHILDREN): moving a subtree would need every level mapped onto another structure, and detaching sub-cards would leave subtasks without their parent on a board that requires one. The moved card's own parent link is dropped (parents are on the same board). The level is kept when the destination has it at or above its work level, else the card takes the destination's work level. Sub-cards in the Bin are detached and restore detached (D130).
  - **Tags: map by name, else drop.** Each tag goes to the destination's tag of the same name, without case; tags it has no namesake for are dropped and returned in `droppedTags` (the toast names them). Tags are not created on the destination (its tag list is the owner's and managers' vocabulary).
  - **Sprint: cleared** (the backlog of the destination).
  - **Relations, comments, reactions, attachments, assignees, flags, due date:** kept. Assignees who cannot open the destination stay and show as Former member (T93), as anywhere else. The card's files become readable to the destination's readers (T462).
  - The revision goes up by one; audited `task.card_move_board` with both boards and both keys. MCP `move_card_to_board` (`tasks:write`), never offered to chat agents (no proposal kind).
